# 本地仓库与代码审查

从「查看 → 仓库与代码审查」或命令面板的「R-IDE: 仓库与代码审查」打开工作台。

## 使用流程

1. 添加项目父目录。应用发现目录内的 Git 仓库与 worktree，选择需要自动更新的仓库后启用。后续发现的仓库默认不更新。
2. 仓库卡片显示分支、跟踪上游、领先/落后数量、本地修改和同步状态。默认每五分钟检查，应用退出后停止。
3. 从工作区变更、提交或分支比较创建审查。审查固定创建时的代码，后续同步不会改变旧批注。通过增量审查创建下一修订。
4. 查看双栏 Diff、提交历史、blame，标记已读或书签并添加行级批注。打开仓库工作区后可用原生搜索、定义与引用导航；语言能力取决于已安装的语言插件。
5. 手动启动 AI 审查，在对话框中选择现有 Codex 模型。已有 Codex 会话繁忙时排队。需要已有 Codex 登录与可用运行时。
6. 导出 Markdown，包含固定版本、文件阅读状态、批注、AI 结论和分析覆盖范围。

## 自动更新与恢复

自动更新只处理当前检出的跟踪分支，不切换分支或推送。本地修改会保存为包含未跟踪文件的 stash，再快进或 rebase 未发布提交，最后恢复暂存区及工作区。忽略文件不进入 stash；如果更新会覆盖它们，则暂停。

未保存编辑器、有 Git 锁、正在 merge/rebase、远端历史重写、已发布提交需要重写、工作区并发变化和恢复冲突都会阻止继续更新。修改编辑器内容后需要保存；若连接中断时编辑器仍脏，保留保护状态，防止后台覆盖。同一页面重新连接后可以解除保护；如果整页重载丢失了编辑器会话，需要核对并保存修改后重启应用。

冲突暂停后可打开仓库处理冲突，并使用「继续恢复」或「中止恢复」。如果 Git 恢复结果无法确定，工作台要求用户明确确认已经恢复并核对了全部本地修改。已完成更新不能通过中止按钮自动重置；原 HEAD 和 stash 保存在 `refs/ride-review/recovery/` 引用下，可手动恢复。

同步产生的 stash 保留在 stash 列表中，使用 `ride-review:<operationId>` 标记。应用不会按 `stash@{n}` 自动删除它：其他 Git 工具可能同时改变序号。确认内容已恢复后，可以在 Git 工具中手动清理。恢复引用也保留至人工清理。

## 快照与 AI 边界

- 快照只读，通过自定义资源 URI 打开；审查批注绑定固定修订和前后版本行号。
- 文件文本上限 1 MiB，每侧快照文本预算 50 MiB。二进制、非 UTF-8、符号链接、子模块和超限文件展示跳过原因。
- AI 按文件分批；每文件前后内容的编码预算为 48 KiB，超限时列出未分析原因。已完成批次在后续失败或取消时保留。
- AI 使用现有共享通道，后端强制只读、禁止提权和联网。运行目录为独立快照。当前固定运行时的只读策略不提供文件系统读取范围隔离，不将它宣传为只能读取快照的安全沙箱。
- 不自动执行审查代码或应用 AI 修改；未配置 AI 时仍可完成全部人工审查。

## 存储与事件

数据保存在 Theia 用户配置目录的 `repository-review` 子目录，包括版本化仓库配置、JSONL 事件与事务日志、审查元数据和快照。普通事件保留 90 天；审查和未解决事务不会随事件过期而删除。

文件监听和定期 Git 核对记录可观察的状态变化。关闭应用期间的操作只能补查结果，不能还原每一步外部命令。远端 PR、评论、CI、系统常驻服务、自动推送和子模块递归更新不在本版本范围内。

## 验证

```powershell
cd app
npm --workspace theia-extensions/codex run build
npm --workspace theia-extensions/review test
npm run build:extensions
npm --workspace applications/browser run build
cd ..
node scripts/sync-upstream.mjs check
```

真实桌面验收使用临时仓库和本地 bare remote，不选择用户的日常仓库：添加父目录、启用自动更新、制造远端提交、同步脏工作区、创建审查、批注、增量审查、导出，再制造冲突并验证恢复。真实 AI 验收需要登录，桌面包装与启动性能需在对应平台实际运行。
